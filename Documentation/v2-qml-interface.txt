TARS-AI V2 Qt/QML interface
============================

TARS-AI V2 uses PySide6 and QML as its native on-device interface. Pygame is
not an active dependency and no Python file under src/ imports it. The retired
implementation is preserved under legacy/pygame/ for source history only.

Architecture
------------

- src/app.py owns the Qt application and QML engine.
- src/qml/main/TarsMain.qml and its components/ directory own layout,
  animation, touch input, and visual state.
- src/qml/fonts/ contains the two bundled display fonts used by production and
  prototype QML entry points.
- src/qml/main/AppRegistry.js is the single launcher registry for app ids,
  titles, icons, source files, availability, and badge categories.
- Reusable QML primitives in components/ provide setting rows, sliders,
  status cards, confirmation prompts, buttons, and standardized application
  loading/error/empty/disabled states.
- src/modules/module_ui_qml.py is the thread-safe Qt property, signal, and slot
  facade. src/modules/module_ui_qml_models.py owns the conversation model and
  camera image provider; module_ui_remote.py owns remote-access operations;
  and module_ui_telemetry.py assembles System Health data. The controller also
  bridges the shared microphone feed and Pi camera into QML without opening
  competing audio devices or writing frames to disk.
- src/modules/module_camera.py owns toolkit-neutral RGB camera capture shared
  by QML, voice vision, identity services, and the browser camera stream.
- src/modules/module_display.py lets skills request an on-device image overlay
  without importing or discovering a particular UI implementation.
- src/modules/module_expression_state.py shares eye moods between the WebUI
  and QML without reaching into an archived application module.
- src/modules/module_runtime.py starts speech, memory, models, skills,
  hardware, web UI, Bluetooth, and vision on a background runtime thread.

Qt remains on the process main thread. Existing TARS services may call the UI
controller from their worker threads; the controller queues all QML model and
property changes back onto the Qt thread.

Raspberry Pi setup
------------------

From the repository root:

    cd ~/TARS-AI-v2
    python3 -m venv --system-site-packages src/.venv
    source src/.venv/bin/activate
    python -m pip install -r requirements-main-ui-qml.txt

The main installer also includes PySide6 for Pi 4 and Pi 5 installations.

Run
---

Run the live TARS application:

    cd ~/TARS-AI-v2
    ./tars-launcher.sh

Run without the graphical interface for diagnostics:

    ./tars-launcher.sh --terminal

Run only the hardware-safe visual prototype:

    cd ~/TARS-AI-v2
    ./run-main-ui-demo.sh --fullscreen

For interface development, the prototype can open a registered app or panel
directly without starting robot hardware:

    python src/app-main-qml.py --app remote
    python src/app-main-qml.py --app dashboard
    python src/app-main-qml.py --app system-health
    python src/app-main-qml.py --panel apps

Dashboard and System Health
---------------------------

Dashboard restores the original weather, five-day forecast, Google News RSS,
ICS calendar, configured quotes, and combined feed in a native QML view. Its
network and parsing work runs in a headless background service, so the Qt main
thread remains responsive and no Pygame/OpenGL dashboard code is loaded.

The dashboard continues to use the original configuration format. On a new
installation, make a private working copy before changing the location or
adding a private calendar URL:

    cp src/dashboard.template.ini src/dashboard.ini

Edit src/dashboard.ini to set location, language, units, news/feed behavior,
quotes, and one or more comma-separated ICS calendar URLs. If dashboard.ini is
absent, the app safely reads dashboard.template.ini. Keep dashboard.ini out of
source control when it contains a private calendar URL.

System Health now owns the four former dashboard telemetry cards and expands
them with memory, disk, uptime, process-thread, hardware, and software status.
Hardware diagnostics report the state already known by the running TARS
services rather than probing I2C devices a second time and competing with the
servo or power-monitor drivers.

Native application views
------------------------

Audio Timeline subscribes to the controller's existing shared microphone
samples. It displays RMS, peak, the observed ambient floor, a diagnostic
speech threshold, voice activity, TTS activity, TARS state, and wake/barge-in
markers. These values are visual diagnostics only: the app does not open a
second audio stream and does not change STT gain, VAD, or wake-word behavior.

Eyes renders every shared expression mood natively in QML and adds automatic
blinks, idle gaze, pointer/touch gaze, state-driven speaking animation, and
touch reactions. Short spoken reactions use the router's serialized on-device
TTS queue, so they cannot start a competing audio playback path.

Avatar reports missing or partial sprite sets instead of silently displaying
a blank panel. It retains neutral-expression and static-frame fallbacks and
shows whether the active frame is native or a fallback. Clock uses an adaptive
portrait/landscape layout, smooth hands, numbered dial, and scalable digital
readout.

Press Esc in a windowed session, or use Menu > Exit Application, to stop the
application cleanly while leaving the Raspberry Pi on. Menu > Restart TARS
restarts only the application. Menu > Shut Down Pi and the header PWR control
both require confirmation before requesting an operating-system shutdown.

Servo calibration handoff
-------------------------

Menu > Servo Calibration safely transfers exclusive PCA9685 ownership to the
standalone QML servo tester. Before the tester opens, TARS stops listening,
cancels active movement, disables PWM output, and releases its PCA9685
connection. The tester starts with PWM output off; support TARS and press
POWER ON only when it is safe to energize the servos.

When the tester closes, TARS reloads saved calibration offsets, reconnects to
the PCA9685, and resumes listening. PWM remains off until a later explicit
movement command, so returning to the main interface does not cause an
automatic pose change.

Display configuration
---------------------

The [UI] section of src/config.ini controls the native interface:

    [UI]
    UI_enabled = True
    fullscreen = True
    show_mouse = False
    screen_width = 480
    screen_height = 800
    rotation = 90

rotation accepts 0, 90, 180, or 270. For a landscape display running the
portrait interface sideways, use rotation = 90 or rotation = 270.

The production TARS display is currently mounted for a 90-degree clockwise
rotation, which src/app.py applies to the complete QML scene. The center signal
display is driven by live samples from the shared microphone hub. The Camera
button opens a live feed supplied through a Qt image provider; closing the
camera returns to the main interface without stopping TARS.

TARS-AI V2 Qt/QML interface
============================

TARS-AI V2 uses PySide6 and QML as its native on-device interface. Pygame is
not loaded by src/app.py.

Architecture
------------

- src/app.py owns the Qt application and QML engine.
- src/qml/main/TarsMain.qml and its components/ directory own layout,
  animation, touch input, and visual state.
- src/modules/module_ui_qml.py is the thread-safe UI state controller and
  conversation model. It also bridges the shared microphone feed and the Pi
  camera into QML without opening competing audio devices or writing frames
  to disk.
- src/modules/module_runtime.py starts speech, memory, models, skills,
  hardware, web UI, Bluetooth, and vision on a background runtime thread.

Qt remains on the process main thread. Existing TARS services may call the UI
controller from their worker threads; the controller queues all QML model and
property changes back onto the Qt thread.

Raspberry Pi setup
------------------

From the repository root:

    cd ~/TARS-AI-v2
    python3 -m venv --system-site-packages src/.venv
    source src/.venv/bin/activate
    python -m pip install -r requirements-main-ui-qml.txt

The main installer also includes PySide6 for Pi 4 and Pi 5 installations.

Run
---

Run the live TARS application:

    cd ~/TARS-AI-v2/src
    source .venv/bin/activate
    python app.py show_ui=true

Run only the hardware-safe visual prototype:

    cd ~/TARS-AI-v2
    ./run-main-ui-demo.sh --fullscreen

Press Esc in a windowed session, or use Menu > Exit Application, to stop the
application cleanly while leaving the Raspberry Pi on. Menu > Restart TARS
restarts only the application. Menu > Shut Down Pi and the header PWR control
both require confirmation before requesting an operating-system shutdown.

Servo calibration handoff
-------------------------

Menu > Servo Calibration safely transfers exclusive PCA9685 ownership to the
standalone QML servo tester. Before the tester opens, TARS stops listening,
cancels active movement, disables PWM output, and releases its PCA9685
connection. The tester starts with PWM output off; support TARS and press
POWER ON only when it is safe to energize the servos.

When the tester closes, TARS reloads saved calibration offsets, reconnects to
the PCA9685, and resumes listening. PWM remains off until a later explicit
movement command, so returning to the main interface does not cause an
automatic pose change.

Display configuration
---------------------

The [UI] section of src/config.ini controls the native interface:

    [UI]
    UI_enabled = True
    fullscreen = True
    show_mouse = False
    screen_width = 480
    screen_height = 800
    rotation = 90

rotation accepts 0, 90, 180, or 270. For a landscape display running the
portrait interface sideways, use rotation = 90 or rotation = 270.

The production TARS display is currently mounted for a 90-degree clockwise
rotation, which src/app.py applies to the complete QML scene. The center signal
display is driven by live samples from the shared microphone hub. The Camera
button opens a live feed supplied through a Qt image provider; closing the
camera returns to the main interface without stopping TARS.
